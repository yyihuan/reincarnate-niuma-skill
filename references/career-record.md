# 职业记录：原文、事实与侧写

这三个层次长期复用，针对某岗位的材料另存。目录名和格式可随用户工作区调整；已有组织方式时沿用它，不另造一套重复档案。

![职业记录与申请材料的关系](../docs/diagrams/career-evidence.svg)

## 记录层次

| 层次 | 保存什么 | 如何引用 |
| --- | --- | --- |
| 原始叙述 | 用户消息、访谈答复、原有文件；保留原件及后续纠正 | 稳定来源编号、文件或消息定位、日期 |
| 事实整理 | 时间线、经历条目、技术与非技术能力、责任范围、结果、空白 | 稳定经历编号和事实编号，回指原文 |
| 职业侧写 | 跨经历的职业轨迹、能力组合、工作环境、倾向和边界 | 引用事实编号，标明归纳与用户认可程度 |
| 岗位申请 | 某一职位的匹配、策略、CV、补充材料与评审 | 引用职业记录，独立版本，不反向覆盖原文 |

一份当前索引足够：列出原始材料覆盖范围、事实条目入口、侧写版本、缺口和各申请的当前采用版本。它只做导航，不复制所有内容。跨会话也先读这一索引。

已有主控台账时只提供结果、证据路径和未结事项，不在这里复制业务状态台账。局部的文件版本索引不是申请进度系统。

## 访谈方法

先问已有材料能否回答的问题之外的内容。每轮通常围绕一个经历或两三个相关缺口；问题数量随回答负担调整，不设必须完成的轮数。

可按需要选用以下方向，不把它整张丢给用户：

- 职业时间线：雇主、岗位、任职时间、转变原因；学校、项目、志愿经历如何进入职业轨迹。
- 日常工作：服务谁，什么事情长期由本人负责，团队如何分工，别人通常会因什么问题来找本人。
- 具体案例：当时的问题和限制、本人做的行动、为何这样选、最终结果、后来怎样维护或交接。
- 范围与成熟度：独立负责还是参与；规模如何确定；只是接触、练习、试验、一次部署，还是持续维护。
- 跨领域能力：技术、硬件、业务理解、沟通、协调、文档、培训、采购或管理等真实经历。
- 选择与偏好：本人喜欢或不想继续的工作、希望发展的方向；不把“做过”直接等同于“喜欢”或“擅长”。

用岗位条件帮助回忆具体例子，例如“有没有需要协调不同使用者的情况”，而不是诱导“你应该也有很强的沟通能力吧”。覆盖完岗位条目后，仍问还有哪些重要经历尚未出现。应届、转行、职业中断或非线性履历均按实际经历处理，不预设已有多年正式工作。

每轮结束给出简短回收：新增事实、需要校正的理解、最影响下一步的一两个空白。用户可补充或表示暂时足够。Agent 不能把沉默视为确认，也不能用“已完整收集”掩盖已知空白。

## 事实条目的最小结构

用 Markdown 表、分节文本或已有数据库均可。重要的是稳定引用和局部检索，不强制引入软件系统。

```yaml
experience_id: E-001
period: 用户确认的时间；不确定处保留精度
employer_and_role: 雇主、岗位以及与客户或合作方的区别
context: 服务对象、问题、环境和限制
responsibility: 本人的行动与决策；团队成果另列
methods: 技术或工作方法，以及实际使用深度
outcome: 可证明结果；没有量化数字时保留定性结果
fact_ids: [F-001, F-002]
sources: 来源编号与具体位置
status: 用户明确陈述／用户已纠正／待确认／Agent归纳
open_questions: 尚未回答的事实空白
tags: 供检索使用的行业、能力、系统、协作和时期标签
```

实际使用时补充必要事实即可，不机械填满字段。数字、年限、英文机构名、规模、归属、客户关系、主导程度和成果尤其需要来源。并行任职不重复累计年限；学习经历不写成生产经验；“部署过”不自动变成“长期负责”。

旧材料包含一句看似确定的话，只证明旧材料写过它。源头是用户的明确叙述时可标记为用户陈述；只有 Agent 旧稿或 Reviewer 的推测时保留待确认。用户明确更正的内容成为当前采用解释，旧记录仍保留并标记被何条更正替代。

## 职业侧写

侧写应覆盖以下有证据的方面，篇幅以能导航后续工作为准：

1. 职业轨迹与雇主／行业环境：每段经历如何形成现在的工作能力。
2. 核心能力及其组合：不只是技能名，而是长期处理的问题与服务对象。
3. 责任与协作：本人承担到哪一层，与谁合作，哪些能力独立完成、哪些依赖团队。
4. 工作方式：从实际案例归纳，例如如何处理限制、排障、维护和取舍；注明这是归纳。
5. 用户自述的动机、偏好与发展意愿，以及暂未证实的解释。
6. 能力边界：直接经验、相邻经验、近期学习、尚无证据的部分。

不要替用户贴人格测试、心理诊断或无法观察的性格标签；与工作无关的敏感属性不进入侧写。不要因为一个目标岗位强调某能力，就把整个人的职业身份改写为该岗位名称。

用事实引用支撑侧写，向用户呈现少量关键归纳供校正。事实核对与定位认可分开记录，不能把用户认可某个定位当成对所有细节的逐条确认。

## 按需检索与增量更新

先看索引和侧写 → 按问题找相关经历／事实编号 → 需要核对时回查原文。条目较多再按雇主、时期或主题拆分，不预建大量空目录。

出现补充或纠正时，追加原文，更新相应事实条目并标记受影响的侧写、匹配结论、CV、补充材料和译文。只重新检查受影响的部分。正文可以保持干净；另存小型“材料版本／段落 → 事实编号”对照用于内部核对，不能加入招聘评审包。
